Интеграционната повърхност на Druma — [публичното API](/bg/integrations/public-api), [Finance API](/bg/integrations/finance-api), входящото [Client API](/bg/integrations/client-api) и изходящите уебхукове — е **версия 1 (v1)**.

## Правила

- **Добавящите промени излизат във v1 без предизвестие.** Нови полета в отговорите, ендпойнти, типове събития на уебхуковете и незадължителни параметри могат да се появят по всяко време. Вашата интеграция трябва да **игнорира непознатите полета**.
- **Несъвместимите промени излизат като v2, наред с v1.** Премахването или преименуването на поле, промяна на типа, значението, удостоверяването или поведението при грешки става само в нова основна версия.
- **v1 остава достъпна поне 6 месеца** след излизането на v2.
- **Оттеглянията се съобщават по три начина:** чрез хедъри в отговорите, имейл до контакта на вашата интеграция и [дневника с промени на API](/bg/integrations/api-changelog).

## Избор на версия

Посочете версията в пътя, в хедър или и на двете места (трябва да съвпадат):

```
GET /public-api/v1/orders
Druma-Api-Version: 1
```

По-старите пътища без версия (`/public-api/orders`) продължават да работят и означават v1. Ако не посочите версия, се използва версията, към която е закрепен вашият API ключ или интеграция (днес v1). Неподдържана версия връща:

```json
{ "error": "unsupported_api_version", "supported": ["1"], "requested": "2" }
```

## Хедъри на отговорите

Всеки отговор на публичното API, Finance API и входящото Client API, включително грешки като `401` и `429`, съдържа:

```
Druma-Api-Version: 1
```

Щом нещо бъде оттеглено, отговорите съдържат и стандартните хедъри:

| Хедър | Значение |
|---|---|
| `Deprecation: @1798761600` | Unix времето на оттеглянето (RFC 9745) |
| `Sunset: Thu, 01 Jul 2027 00:00:00 GMT` | Датата, след която може да спре да работи (RFC 8594) |
| `Link: <https://docs.druma.io/...>; rel="deprecation"` | Къде е ръководството за миграция |

Ако клиентът ви записва тези хедъри, ще видите оттеглянето много преди нещо да спре да работи.

## Уебхукове

Тялото на всеки уебхук запазва всички съществуващи полета и добавя:

| Поле | Значение |
|---|---|
| `api_version` | Версията на API: `"1"` |
| `event_id` | Уникален идентификатор на събитието. **Остава същият, когато Druma повтаря доставката**, затова го използвайте, за да игнорирате дубликати. |

Всяка доставка съдържа и хедърите `X-Druma-Event-Id`, `X-Druma-Event-Type`, `X-Druma-Timestamp` (Unix секунди) и `Druma-Api-Version`.

<Note>
`api_version` и `event_id` са **запазени** ключове. Druma ги добавя след прилагането на вашето изходящо съпоставяне на полета, така че винаги запазват имената си, а съпоставянето не може да ги преименува или презапише. Не ги използвайте като цели на съпоставянето.
</Note>

### Проверка на подписите (HMAC-SHA256)

При тип удостоверяване **HMAC-SHA256** всяка доставка е подписана с вашата споделена тайна в два хедъра:

| Хедър | Стойност |
|---|---|
| `X-Druma-Signature` | `sha256=<hex>`, HMAC-SHA256 на суровото тяло. Непроменен, запазен за съществуващите интеграции. Няма времеви печат, затова не открива повторно изпратена заявка. |
| `X-Druma-Signature-V2` | `t=<unix секунди>,v1=<hex>`, HMAC-SHA256 на `"<t>.<суровото тяло>"`. Времевият печат е част от подписаното, така че можете да отхвърляте стари заявки. **Използвайте него за нови интеграции.** |

Проверявайте спрямо **суровото** тяло на заявката, не спрямо повторно сериализирано копие. В Node:

```js
import crypto from 'node:crypto';

export function verifyDrumaWebhook(rawBody, headers, secret, toleranceSeconds = 300) {
  const header = headers['x-druma-signature-v2'] ?? '';
  const parts = Object.fromEntries(header.split(',').map((p) => p.split('=')));
  const t = Number(parts.t);
  if (!Number.isFinite(t) || !parts.v1) return false;
  if (Math.abs(Date.now() / 1000 - t) > toleranceSeconds) return false;
  const expected = crypto.createHmac('sha256', secret).update(`${t}.${rawBody}`).digest('hex');
  const a = Buffer.from(expected);
  const b = Buffer.from(parts.v1);
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}
```

Приемайте доставка само ако подписът е верен и нейното `event_id` не е обработвано преди. Потвърдете с произволен статус `2xx`; другите отговори се повтарят по график с нарастващи интервали. `X-Druma-Timestamp` се обновява при всеки опит, така че повторен опит не се отхвърля от прозореца срещу повторно възпроизвеждане. Хедърът V2 се изпраща само при тип удостоверяване **HMAC-SHA256**.

## Справочник на API

Справочникът OpenAPI 3.1 за всеки ендпойнт е в навигацията в групата **API reference** (публичното API и Finance API). Базов URL: `https://YOUR-PROJECT.supabase.co/functions/v1`, след това `/public-api/v1/...` или `/finance-api/v1/...`.
