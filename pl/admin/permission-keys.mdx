Skorzystaj z tej strony, tworząc rolę niestandardową w Ustawienia → Użytkownicy → Role. Przy każdym uprawnieniu podano dokładny dostęp, który daje, miejsce, w którym Druma je sprawdza, oraz role wbudowane, które mają je domyślnie. Strona jest generowana z tej samej konfiguracji, na której działa aplikacja, więc nie może rozjechać się z jej działaniem.

<Note>Nazwy uprawnień, obszarów i ról są wyświetlane w tym języku. Szczegółowe opisy są utrzymywane po angielsku.</Note>

## Jak czytać wpis

Domyślnie mają je wymienia role wbudowane z tym uprawnieniem. W kreatorze ról mówi, czy administrator firmy może je zaznaczyć w roli niestandardowej. Egzekwowane w mówi, czy sprawdzenie odbywa się w ekranach aplikacji, w bazie danych, czy w obu: uprawnienie sprawdzane tylko w aplikacji ukrywa przyciski, ale nie powstrzyma bezpośredniego wywołania, a uprawnienie, którego nic nie sprawdza, na razie nic nie zmienia. Wymaga także wymienia uprawnienia przydatne tylko razem.

## Zlecenia

Tworzenie, edytowanie i usuwanie zleceń, a także notatki do zlecenia i pola cenowe.

### Podgląd zleceń

`orders:read`

- **Domyślnie mają je:** Administrator, Administrator firmy, Kluczowy użytkownik, Planista, Dyspozytor, Obsługa klienta, Raportowanie, Sprzedaż
- **W kreatorze ról:** Można zaznaczyć
- **Egzekwowane w:** Ekrany aplikacji i baza danych

**Co daje.** Opens Operations: the order list, order detail, forwarding and everything shown on an order (legs, stops, references, documents, communications, pallets, templates, e-Transport assignments, status events). Also feeds global search and the sidebar badge counts.

**Gdzie jest egzekwowane.** The Operations section and its routes ask for it; the database uses it as the row-level read gate on orders and roughly a hundred order-related tables (order_legs, order_references, order_tasks, order_communications, templates, goods lines, status events and more). It does not allow any change.

### Tworzenie zleceń

`orders:create`

- **Domyślnie mają je:** Administrator, Administrator firmy, Kluczowy użytkownik, Planista, Obsługa klienta, Sprzedaż
- **W kreatorze ról:** Można zaznaczyć
- **Egzekwowane w:** Ekrany aplikacji i baza danych
- **Wymaga także:** `orders:read`, `commercial:manage`

**Co daje.** Create new orders: the New order action, copying an order, creating several orders from a spec, scanning an order document, and creating orders from templates (including scheduled template runs).

**Gdzie jest egzekwowane.** Both, but in two layers. The screens and the RPCs/Edge Functions behind them (next_order_number, copy_order, create_orders_from_spec, instantiate_order_template, document-scan, order-template-scheduler) check this key. The INSERT into the orders table itself is checked against the database key commercial:manage, which the role builder cannot grant: a custom role holding orders:create but not commercial:manage is stopped at that insert.

### Edycja zleceń

`orders:edit`

- **Domyślnie mają je:** Administrator, Administrator firmy, Kluczowy użytkownik, Planista, Obsługa klienta
- **W kreatorze ról:** Można zaznaczyć
- **Egzekwowane w:** Ekrany aplikacji i baza danych
- **Wymaga także:** `orders:read`, `commercial:manage`

**Co daje.** Change existing orders in the places the app lets you edit them: order drawers, subcontracting and carrier assignment, groupage and forwarding panels, VAT and extras, cancelling a sold or subcontracted order, resolving eCMR exceptions and automation jobs, handling client delay notices, approving or rejecting platform proof-of-delivery, e-Transport vehicle change and GPS pause actions.

**Gdzie jest egzekwowane.** Screens ask for it, and about fifty RPCs check it (cancel_subcontractor, cancel_sell_order, dissolve_groupage, set_preloaded_trailer, resolve_ecmr_exception, approve_transporeon_pod, write_off_remainder and others), as do the transporeon-api, inbound-order-email and client-api-admin Edge Functions. The UPDATE on the orders row itself is checked against commercial:manage (not selectable in the role builder): a custom role needs both.

### Usuwanie zleceń

`orders:delete`

- **Domyślnie mają je:** Administrator, Administrator firmy, Kluczowy użytkownik, Planista, Obsługa klienta
- **W kreatorze ról:** Można zaznaczyć
- **Egzekwowane w:** Obecnie nic go nie egzekwuje

**Co daje.** Intended to allow deleting orders.

**Gdzie jest egzekwowane.** None today. No screen, RPC, policy or Edge Function reads this key. Deleting an order is decided by the database key commercial:manage (the orders DELETE policy). Granting orders:delete to a custom role changes nothing.

### Dodawanie notatek do zlecenia

`orders:notes`

- **Domyślnie mają je:** Administrator, Administrator firmy, Kluczowy użytkownik, Planista, Dyspozytor, Obsługa klienta, Raportowanie, Sprzedaż
- **W kreatorze ról:** Można zaznaczyć
- **Egzekwowane w:** Baza danych i funkcje serwera

**Co daje.** Read and add internal order notes, and let Ask Druma read them.

**Gdzie jest egzekwowane.** The order_notes table (SELECT and INSERT policies) and the Ask Druma notes tool check it. No screen hides notes on its own.

### Podgląd/edycja statusu fakturowania

### Podgląd własnych zleceń

`orders:read_own`

- **Domyślnie mają je:** Kierowca, Klient
- **W kreatorze ról:** Można zaznaczyć
- **Egzekwowane w:** Tylko ekrany aplikacji

**Co daje.** The driver or client sees only the orders that belong to them (their own loads or shipments).

**Gdzie jest egzekwowane.** App marker only: the app uses it to recognise accounts that have no office read access (for example roster-only mode). Row access for drivers is enforced by the orders SELECT policy through driver assignment, not by this key. Exempt from the grant ceiling.

### Korekta przypisania ciężarówki/naczepy/kierowcy

`orders:correct_assignment`

**Co daje.** Retroactively correct the truck, trailer and driver on a past leg, insert or remove relays, void or add stops, resequence stops, reopen a leg, correct terminal status, e-Transport UIT, subcontract carrier and rate, and groupage run assignment: the correction workspace of the Key User hub.

**Gdzie jest egzekwowane.** The correction workspace and planning-board correct-assignment dialogs check it; the correct_* RPCs and _assignment_correction_can_correct check it in the database, usually together with data:correct, a reason and the correctable-fields catalogue.

### Pominięcie blokady kredytowej

**Gdzie jest egzekwowane.** The credit-stop override modal checks it; the RPC override_client_credit_stop checks it and records the override.

### Popraw dane w zamkniętych rekordach

`data:correct`

- **Domyślnie mają je:** Administrator, Administrator firmy, Kluczowy użytkownik
- **W kreatorze ról:** Można zaznaczyć
- **Egzekwowane w:** Ekrany aplikacji i baza danych

**Co daje.** Open the Key User hub and correct allow-listed fields on records the normal workflow no longer exposes (closed trips, delivered orders, invoices, payments, expense decisions), with a mandatory reason and a full audit trail; also resolve key-user fix requests.

**Gdzie jest egzekwowane.** The Key User route, the closed-record lock host and the correction dialogs ask for it; apply_data_correction, correction_impact_preflight, revert_correction, resolve_key_user_request and some forty correct_* / reverse_* RPCs check it, and the key alone grants nothing: the (entity, column) pair must be in the correctable_fields catalogue and a reason is required.

**Gdzie jest egzekwowane.** App for the screens (mobile nav, Coverage queue, customer-service mobile model); the database uses it to pick the recipients of the trucks-without-reload notification (notify_trucks_without_reload, via company_users_with_permission).

- **Domyślnie mają je:** Administrator, Administrator firmy, Planista, Dyspozytor

**Gdzie jest egzekwowane.** Database only, and only as a recipient rule: the escalation notification is sent to users holding this key (company_users_with_permission). It is not a screen or write gate.
