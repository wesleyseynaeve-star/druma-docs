Zmiany w obrębie v1 są addytywne. Zmiany łamiące i wycofania są tu ogłaszane jako pierwsze. Zasady opisuje [Wersjonowanie API](/pl/integrations/api-versioning).

## 2026-10-23

**Dodano (v1, nie wymaga działań)**

- **Idempotentne przyjmowanie.** `inbound-client-api` akceptuje opcjonalny nagłówek `Idempotency-Key`. Powtórzenie zakończonego klucza zwraca `200` z oryginalnym zleceniem i nagłówkiem `Idempotent-Replayed: true`; powtórzenie, gdy pierwsze żądanie jeszcze trwa, zwraca `409` `{"error":"in_progress"}` z `Retry-After: 5`; ten sam klucz z inną treścią zwraca `422` `{"error":"idempotency_key_reused"}`. Bez klucza, jak dotąd, nie ma deduplikacji.
- **`outcome` w przychodzącym `200`.** Addytywny ciąg znaków (`created`, `applied_draft`, `parked`, `cancelled_draft`, `cancel_parked`, `ignored_terminal`, `ignored_stale`, `unchanged`, `ignored_pending_cancel`, `duplicate_external_id`, `not_found`). Traktuj go jako otwartą listę. `status` w odpowiedzi na utworzenie może mieć wartość `pending`, gdy operator włączy pomijanie wersji roboczej dla połączenia.
- **Zastępowanie i anulowanie.** Mapowanie czytające `message_function` i `external_id` zamienia późniejszą wiadomość w zmianę utworzonego zlecenia. Nowe kody `422`: `external_id_required`, `unknown_message_function`.
- **Więcej formatów żądań.** XML (SAP IDoc), EDIFACT i `text/csv` obok JSON; jedna wiadomość na żądanie (inaczej `422` `{"error":"multi_message_not_supported"}`).
- **Nowe opcjonalne zdarzenia webhooka.** `order.declined`, `stop.arrived.loading`, `stop.departed.loading`, `stop.arrived.offloading`, `stop.departed.offloading` i `order.pod_uploaded` (wysyłane dopiero po zatwierdzeniu POD przez planistę). Dostarczane tylko połączeniom, które je wymieniają; żadne istniejące połączenie się nie zmienia.
- **`references` w zdarzeniach zlecenia i przystanku.** Jeden opcjonalny obiekt `{ "<key>": "<value>" }` z własnymi referencjami klienta, które operator oznaczył jako widoczne dla klienta. Brak, gdy zlecenie nie ma żadnej.
- **Mapowanie wychodzące.** Połączenie może wysyłać XML, EDIFACT lub JSON w układzie klienta z jego kodami statusów; zdarzenie bez przypisanego statusu jest pomijane (nie wysyłane, nie ponawiane). Bez mapowania wychodzącego treść jest bajt w bajt taka sama jak wcześniej.
- **OAuth2 client credentials** jako typ uwierzytelniania wychodzącego, obok bearer, basic, HMAC i none.

**Wycofane / usunięte:** nic.

## 2026-10-10

**Dodano (v1, bez konieczności działania)**

- **Nagłówki wersji.** Każda odpowiedź Publicznego API, Finance API i przychodzącego Client API zawiera `Druma-Api-Version: 1`. Możesz też wysyłać ten nagłówek w żądaniach.
- **Ścieżki `/v1/`.** Działają teraz `/public-api/v1/orders` i `/finance-api/v1/billable`. Dotychczasowe ścieżki bez wersji są bez zmian i oznaczają v1.
- **`event_id` i `api_version` w webhookach.** Każde ciało webhooka zyskuje te dwa pola. `event_id` jest stały przy ponowieniach, użyj go do deduplikacji.
- **Nagłówki webhooków.** `X-Druma-Event-Id`, `X-Druma-Event-Type`, `X-Druma-Timestamp` i `Druma-Api-Version` przy każdej dostawie.
- **Podpis ze znacznikiem czasu.** Dostawy HMAC dodają `X-Druma-Signature-V2: t=<unix>,v1=<hex>` jako ochronę przed powtórką. `X-Druma-Signature` bez zmian.
- **Dokumentacja OpenAPI 3.1** dla Publicznego API i Finance API.

**Wycofane / usunięte:** nic.
