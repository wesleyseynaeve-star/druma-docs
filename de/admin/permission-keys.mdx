Nutzen Sie diese Seite, wenn Sie in Einstellungen → Benutzer → Rollen eine benutzerdefinierte Rolle erstellen. Jede Berechtigung nennt den genauen Zugriff, den sie gibt, wo Druma sie prüft und welche integrierten Rollen sie standardmäßig haben. Die Seite wird aus derselben Konfiguration erzeugt, auf der die App läuft, und kann daher nicht vom Verhalten der App abweichen.

<Note>Namen von Berechtigungen, Bereichen und Rollen werden in dieser Sprache angezeigt. Die ausführlichen Beschreibungen werden auf Englisch gepflegt.</Note>

## So lesen Sie einen Eintrag

Standardmäßig vergeben an listet die integrierten Rollen mit dieser Berechtigung. Im Rollen-Editor zeigt, ob ein Unternehmensadministrator sie in einer benutzerdefinierten Rolle anhaken kann. Durchgesetzt in zeigt, ob die Prüfung in den App-Bildschirmen, in der Datenbank oder in beiden stattfindet: Eine nur in der App geprüfte Berechtigung blendet Schaltflächen aus, verhindert aber keinen direkten Aufruf, und eine, die nichts prüft, ändert noch nichts. Benötigt außerdem nennt Berechtigungen, die nur zusammen sinnvoll sind.

## Aufträge

Aufträge erstellen, bearbeiten und löschen sowie Auftragsnotizen und Preisfelder.

### Aufträge ansehen

`orders:read`

- **Standardmäßig vergeben an:** Administrator, Unternehmensadmin, Key User, Planer, Disponent, Kundendienst, Reporting, Vertrieb
- **Im Rollen-Editor:** Kann angehakt werden
- **Durchgesetzt in:** App-Bildschirme und Datenbank

**Was sie gewährt.** Opens Operations: the order list, order detail, forwarding and everything shown on an order (legs, stops, references, documents, communications, pallets, templates, e-Transport assignments, status events). Also feeds global search and the sidebar badge counts.

**Wo sie durchgesetzt wird.** The Operations section and its routes ask for it; the database uses it as the row-level read gate on orders and roughly a hundred order-related tables (order_legs, order_references, order_tasks, order_communications, templates, goods lines, status events and more). It does not allow any change.

### Aufträge erstellen

`orders:create`

- **Standardmäßig vergeben an:** Administrator, Unternehmensadmin, Key User, Planer, Kundendienst, Vertrieb
- **Im Rollen-Editor:** Kann angehakt werden
- **Durchgesetzt in:** App-Bildschirme und Datenbank
- **Benötigt außerdem:** `orders:read`, `commercial:manage`

**Was sie gewährt.** Create new orders: the New order action, copying an order, creating several orders from a spec, scanning an order document, and creating orders from templates (including scheduled template runs).

**Wo sie durchgesetzt wird.** Both, but in two layers. The screens and the RPCs/Edge Functions behind them (next_order_number, copy_order, create_orders_from_spec, instantiate_order_template, document-scan, order-template-scheduler) check this key. The INSERT into the orders table itself is checked against the database key commercial:manage, which the role builder offers as a database permission: a custom role holding orders:create but not commercial:manage is stopped at that insert.

### Aufträge bearbeiten

`orders:edit`

- **Standardmäßig vergeben an:** Administrator, Unternehmensadmin, Key User, Planer, Kundendienst
- **Im Rollen-Editor:** Kann angehakt werden
- **Durchgesetzt in:** App-Bildschirme und Datenbank
- **Benötigt außerdem:** `orders:read`, `commercial:manage`

**Was sie gewährt.** Change existing orders in the places the app lets you edit them: order drawers, subcontracting and carrier assignment, groupage and forwarding panels, VAT and extras, cancelling a sold or subcontracted order, resolving eCMR exceptions and automation jobs, handling client delay notices, approving or rejecting platform proof-of-delivery, e-Transport vehicle change and GPS pause actions.

**Wo sie durchgesetzt wird.** Screens ask for it, and about fifty RPCs check it (cancel_subcontractor, cancel_sell_order, dissolve_groupage, set_preloaded_trailer, resolve_ecmr_exception, approve_transporeon_pod, write_off_remainder and others), as do the transporeon-api, inbound-order-email and client-api-admin Edge Functions. The UPDATE on the orders row itself is checked against commercial:manage (a database permission the role builder offers): a custom role needs both.

### Aufträge löschen

`orders:delete`

- **Standardmäßig vergeben an:** Administrator, Unternehmensadmin, Key User, Planer, Kundendienst, Vertrieb
- **Im Rollen-Editor:** Kann angehakt werden
- **Durchgesetzt in:** App-Bildschirme und Datenbank
- **Benötigt außerdem:** `orders:read`, `commercial:manage`

**Was sie gewährt.** Move an order into the deleted state: the Delete / Discard buttons on the order list, the intake workbench (single and bulk) and the planning board, and the clean-up of a placeholder order after linking or saving.

**Wo sie durchgesetzt wird.** Screens hide the delete controls without it. In the database the trigger trg_orders_soft_delete_needs_permission refuses an authenticated user who sets orders.deleted_at without it (42501 order_delete_needs_permission); the orders DELETE policy needs it together with commercial:manage. System paths (correction reverts, cron, service role, other SECURITY DEFINER functions) are not affected. Restoring a deleted order stays under the normal update rule.

### Auftragsnotizen hinzufügen

`orders:notes`

- **Standardmäßig vergeben an:** Administrator, Unternehmensadmin, Key User, Planer, Disponent, Kundendienst, Reporting, Vertrieb
- **Im Rollen-Editor:** Kann angehakt werden
- **Durchgesetzt in:** Datenbank und Serverfunktionen

**Was sie gewährt.** Read and add internal order notes, and let Ask Druma read them.

**Wo sie durchgesetzt wird.** The order_notes table (SELECT and INSERT policies) and the Ask Druma notes tool check it. No screen hides notes on its own.

- **Im Rollen-Editor:** Kann angehakt werden
- **Durchgesetzt in:** App-Bildschirme und Datenbank

**Was sie gewährt.** See and edit the price agreed with the client on an order, on templates, in the Pricing views and in revenue analytics.

**Wo sie durchgesetzt wird.** Screens check it; the trigger enforce_orders_financial_column_permissions blocks writing the agreed-price columns without it; create_orders_from_spec, copy_order, template RPCs and the revenue analytics RPCs check it; the order-price-apply and order-template-scheduler Edge Functions check it.

### Rechnungsstatus ansehen/bearbeiten

`orders:invoice_status`

- **Standardmäßig vergeben an:** Administrator, Unternehmensadmin, Key User, Planer, Kundendienst, Reporting
- **Im Rollen-Editor:** Kann angehakt werden
- **Durchgesetzt in:** App-Bildschirme und Datenbank
- **Benötigt außerdem:** `orders:edit`

**Was sie gewährt.** Edit the invoice status and VAT section of an order.

**Wo sie durchgesetzt wird.** The order VAT section is editable only with orders:edit and this key together; the trigger enforce_orders_financial_column_permissions blocks changing the invoice-status columns without it.

### Eigene Aufträge ansehen

`orders:read_own`

- **Standardmäßig vergeben an:** Fahrer, Kunde
- **Im Rollen-Editor:** Kann angehakt werden
- **Durchgesetzt in:** Nur App-Bildschirme

**Was sie gewährt.** The driver or client sees only the orders that belong to them (their own loads or shipments).

**Wo sie durchgesetzt wird.** App marker only: the app uses it to recognise accounts that have no office read access (for example roster-only mode). Row access for drivers is enforced by the orders SELECT policy through driver assignment, not by this key. Exempt from the grant ceiling.

### Lkw-/Anhänger-/Fahrerzuweisung korrigieren

`orders:correct_assignment`

- **Standardmäßig vergeben an:** Administrator, Unternehmensadmin, Key User
- **Im Rollen-Editor:** Kann angehakt werden
- **Durchgesetzt in:** App-Bildschirme und Datenbank
- **Benötigt außerdem:** `data:correct`

**Was sie gewährt.** Retroactively correct the truck, trailer and driver on a past leg, insert or remove relays, void or add stops, resequence stops, reopen a leg, correct terminal status, e-Transport UIT, subcontract carrier and rate, and groupage run assignment: the correction workspace of the Key User hub.

**Wo sie durchgesetzt wird.** The correction workspace and planning-board correct-assignment dialogs check it; the correct_* RPCs and _assignment_correction_can_correct check it in the database, usually together with data:correct, a reason and the correctable-fields catalogue.

### Kreditstopp umgehen

`orders:override_credit_stop`

- **Standardmäßig vergeben an:** Administrator, Unternehmensadmin, Key User, Planer
- **Im Rollen-Editor:** Kann angehakt werden
- **Durchgesetzt in:** App-Bildschirme und Datenbank

**Was sie gewährt.** Release an order that the client credit-stop guard blocked (override for a single order).

**Wo sie durchgesetzt wird.** The credit-stop override modal checks it; the RPC override_client_credit_stop checks it and records the override.

### Anhänger-Ausstattungskonflikt übersteuern

`orders:override_equipment`

- **Standardmäßig vergeben an:** Administrator, Unternehmensadmin, Key User, Planer
- **Im Rollen-Editor:** Kann angehakt werden

**Was sie gewährt.** Assign a trailer that fails the order equipment requirement (tail lift, ADR, temperature and so on) anyway, with the mismatch recorded.

**Wo sie durchgesetzt wird.** The confirm-assignment sheet shows the override only with it; override_equipment_mismatch checks it and writes equipment_overrides.

### Daten in abgeschlossenen Datensätzen korrigieren

`data:correct`

- **Standardmäßig vergeben an:** Administrator, Unternehmensadmin, Key User
- **Im Rollen-Editor:** Kann angehakt werden
- **Durchgesetzt in:** App-Bildschirme und Datenbank

**Was sie gewährt.** Open the Key User hub and correct allow-listed fields on records the normal workflow no longer exposes (closed trips, delivered orders, invoices, payments, expense decisions), with a mandatory reason and a full audit trail; also resolve key-user fix requests.

**Wo sie durchgesetzt wird.** The Key User route, the closed-record lock host and the correction dialogs ask for it; apply_data_correction, correction_impact_preflight, revert_correction, resolve_key_user_request and some forty correct_* / reverse_* RPCs check it, and the key alone grants nothing: the (entity, column) pair must be in the correctable_fields catalogue and a reason is required.

### Auftrag an den Disponenten eskalieren

`orders:escalate`

- **Standardmäßig vergeben an:** Administrator, Unternehmensadmin, Planer, Disponent, Kundendienst
- **Im Rollen-Editor:** Kann angehakt werden
- **Durchgesetzt in:** App-Bildschirme und Datenbank

**Was sie gewährt.** Escalate an order to the planner, and use the gap-coverage queue and truck-coverage views (trucks without a reload). Holders also receive the "trucks without reload" reload alerts.

**Wo sie durchgesetzt wird.** App for the screens (mobile nav, Coverage queue, customer-service mobile model); the database uses it to pick the recipients of the trucks-without-reload notification (notify_trucks_without_reload, via company_users_with_permission).

### Auftragseskalation lösen

`orders:escalation_resolve`

- **Standardmäßig vergeben an:** Administrator, Unternehmensadmin, Planer, Disponent
- **Im Rollen-Editor:** Kann angehakt werden
- **Durchgesetzt in:** Datenbank und Serverfunktionen

**Was sie gewährt.** Resolve an order escalation. Holders are also the recipients of escalation notifications.

**Wo sie durchgesetzt wird.** Database only, and only as a recipient rule: the escalation notification is sent to users holding this key (company_users_with_permission). It is not a screen or write gate.

### Aufträge, Kunden, Angebote und Subunternehmer schreiben

`commercial:manage`

- **Standardmäßig vergeben an:** Administrator, Unternehmensadmin, Key User, Planer, Kundendienst, Vertrieb
- **Im Rollen-Editor:** Kann angehakt werden
- **Durchgesetzt in:** Datenbank und Serverfunktionen

**Was sie gewährt.** The commercial write set: create, edit and delete orders (with legs, stops, extras and goods), clients and their contacts, quotes, tenders, subcontractors and their documents, CRM contacts and deals, capacity contracts, client instructions, groupage orders and handling units; read price lists and rate cards.

**Wo sie durchgesetzt wird.** Database only (policies on dozens of tables, notably the INSERT/UPDATE/DELETE policies of orders, clients, quotes, tenders and subcontractors, and several RPCs and Edge Functions such as client-portal-token). The role builder offers it as a database permission (DRUMA-1595): a custom role needs it, in addition to orders:create, orders:edit or clients:manage, to write these tables.

## Berechtigungen der Datenbankebene

Diese Berechtigungen benennen in der Datenbank eine Rollenmenge für die Sicherheit auf Zeilenebene. Sofern nicht als auswählbar gekennzeichnet, können sie keiner benutzerdefinierten Rolle gegeben werden. Eine benutzerdefinierte Rolle ohne sie kann die geschützten Tabellen nicht schreiben, auch wenn die passende App-Berechtigung angehakt ist.

### capi_library:manage

`capi_library:manage`

- **Standardmäßig vergeben an:** Administrator
- **Im Rollen-Editor:** Nicht auswählbar
- **Durchgesetzt in:** Datenbank und Serverfunktionen

**Was sie gewährt.** Druma staff only: edit the shared known-format library that recognises client order messages (SAP IDoc, EDIFACT, JSON freight orders), publish revisions and mark them verified.

**Wo sie durchgesetzt wird.** The capi_library_* functions and the capi-library-admin Edge Function check it; the library tables have no tenant policy. Held by the platform admin alone, never grantable by a company admin.
