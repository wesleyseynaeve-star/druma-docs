Utilisez cette page lorsque vous créez un rôle personnalisé dans Paramètres → Utilisateurs → Rôles. Chaque permission indique l'accès exact qu'elle donne, où Druma la vérifie et quels rôles intégrés la détiennent par défaut. La page est générée à partir de la configuration même de l'application ; elle ne peut donc pas s'écarter de son comportement.

<Note>Les noms des permissions, des domaines et des rôles sont affichés dans cette langue. Les descriptions détaillées sont maintenues en anglais.</Note>

## Comment lire une entrée

Détenue par défaut liste les rôles intégrés qui ont la permission. Dans le créateur de rôles indique si un administrateur d'entreprise peut la cocher dans un rôle personnalisé. Appliquée dans indique si la vérification a lieu dans les écrans de l'application, dans la base de données, ou les deux : une permission vérifiée uniquement dans l'application masque des boutons mais n'empêche pas un appel direct, et une permission que rien ne vérifie ne change encore rien. Nécessite aussi liste les permissions qui ne servent qu'ensemble.

## Commandes

Créer, modifier et supprimer des commandes, ainsi que les notes et les champs de tarification.

### Voir les commandes

`orders:read`

- **Détenue par défaut:** Admin, Admin entreprise, Utilisateur cle, Planificateur, Dispatcheur, Service client, Reporting, Commercial
- **Dans le créateur de rôles:** Peut être cochée
- **Appliquée dans:** Écrans de l'application et base de données

**Ce qu'elle accorde.** Opens Operations: the order list, order detail, forwarding and everything shown on an order (legs, stops, references, documents, communications, pallets, templates, e-Transport assignments, status events). Also feeds global search and the sidebar badge counts.

**Où elle est appliquée.** The Operations section and its routes ask for it; the database uses it as the row-level read gate on orders and roughly a hundred order-related tables (order_legs, order_references, order_tasks, order_communications, templates, goods lines, status events and more). It does not allow any change.

### Créer des commandes

`orders:create`

- **Détenue par défaut:** Admin, Admin entreprise, Utilisateur cle, Planificateur, Service client, Commercial
- **Dans le créateur de rôles:** Peut être cochée
- **Appliquée dans:** Écrans de l'application et base de données
- **Nécessite aussi:** `orders:read`, `commercial:manage`

**Ce qu'elle accorde.** Create new orders: the New order action, copying an order, creating several orders from a spec, scanning an order document, and creating orders from templates (including scheduled template runs).

**Où elle est appliquée.** Both, but in two layers. The screens and the RPCs/Edge Functions behind them (next_order_number, copy_order, create_orders_from_spec, instantiate_order_template, document-scan, order-template-scheduler) check this key. The INSERT into the orders table itself is checked against the database key commercial:manage, which the role builder offers as a database permission: a custom role holding orders:create but not commercial:manage is stopped at that insert.

### Modifier des commandes

`orders:edit`

- **Détenue par défaut:** Admin, Admin entreprise, Utilisateur cle, Planificateur, Service client
- **Dans le créateur de rôles:** Peut être cochée
- **Appliquée dans:** Écrans de l'application et base de données
- **Nécessite aussi:** `orders:read`, `commercial:manage`

**Ce qu'elle accorde.** Change existing orders in the places the app lets you edit them: order drawers, subcontracting and carrier assignment, groupage and forwarding panels, VAT and extras, cancelling a sold or subcontracted order, resolving eCMR exceptions and automation jobs, handling client delay notices, approving or rejecting platform proof-of-delivery, e-Transport vehicle change and GPS pause actions.

**Où elle est appliquée.** Screens ask for it, and about fifty RPCs check it (cancel_subcontractor, cancel_sell_order, dissolve_groupage, set_preloaded_trailer, resolve_ecmr_exception, approve_transporeon_pod, write_off_remainder and others), as do the transporeon-api, inbound-order-email and client-api-admin Edge Functions. The UPDATE on the orders row itself is checked against commercial:manage (a database permission the role builder offers): a custom role needs both.

### Supprimer des commandes

`orders:delete`

- **Détenue par défaut:** Admin, Admin entreprise, Utilisateur cle, Planificateur, Service client, Commercial
- **Dans le créateur de rôles:** Peut être cochée
- **Appliquée dans:** Écrans de l'application et base de données
- **Nécessite aussi:** `orders:read`, `commercial:manage`

**Ce qu'elle accorde.** Move an order into the deleted state: the Delete / Discard buttons on the order list, the intake workbench (single and bulk) and the planning board, and the clean-up of a placeholder order after linking or saving.

**Où elle est appliquée.** Screens hide the delete controls without it. In the database the trigger trg_orders_soft_delete_needs_permission refuses an authenticated user who sets orders.deleted_at without it (42501 order_delete_needs_permission); the orders DELETE policy needs it together with commercial:manage. System paths (correction reverts, cron, service role, other SECURITY DEFINER functions) are not affected. Restoring a deleted order stays under the normal update rule.

### Voir ses propres commandes

`orders:read_own`

- **Détenue par défaut:** Chauffeur, Client
- **Dans le créateur de rôles:** Peut être cochée
- **Appliquée dans:** Écrans de l'application uniquement

**Ce qu'elle accorde.** The driver or client sees only the orders that belong to them (their own loads or shipments).

**Où elle est appliquée.** App marker only: the app uses it to recognise accounts that have no office read access (for example roster-only mode). Row access for drivers is enforced by the orders SELECT policy through driver assignment, not by this key. Exempt from the grant ceiling.

### Corriger l'affectation camion/remorque/chauffeur

`orders:correct_assignment`

- **Détenue par défaut:** Admin, Admin entreprise, Utilisateur cle
- **Dans le créateur de rôles:** Peut être cochée
- **Appliquée dans:** Écrans de l'application et base de données
- **Nécessite aussi:** `data:correct`

**Ce qu'elle accorde.** Retroactively correct the truck, trailer and driver on a past leg, insert or remove relays, void or add stops, resequence stops, reopen a leg, correct terminal status, e-Transport UIT, subcontract carrier and rate, and groupage run assignment: the correction workspace of the Key User hub.

**Où elle est appliquée.** The correction workspace and planning-board correct-assignment dialogs check it; the correct_* RPCs and _assignment_correction_can_correct check it in the database, usually together with data:correct, a reason and the correctable-fields catalogue.

### Corriger des données sur des enregistrements clôturés

`data:correct`

- **Détenue par défaut:** Admin, Admin entreprise, Utilisateur cle
- **Dans le créateur de rôles:** Peut être cochée
- **Appliquée dans:** Écrans de l'application et base de données

**Ce qu'elle accorde.** Open the Key User hub and correct allow-listed fields on records the normal workflow no longer exposes (closed trips, delivered orders, invoices, payments, expense decisions), with a mandatory reason and a full audit trail; also resolve key-user fix requests.

**Où elle est appliquée.** The Key User route, the closed-record lock host and the correction dialogs ask for it; apply_data_correction, correction_impact_preflight, revert_correction, resolve_key_user_request and some forty correct_* / reverse_* RPCs check it, and the key alone grants nothing: the (entity, column) pair must be in the correctable_fields catalogue and a reason is required.

### Escalader une commande au planificateur

`orders:escalate`

- **Détenue par défaut:** Admin, Admin entreprise, Planificateur, Dispatcheur, Service client
- **Dans le créateur de rôles:** Peut être cochée
- **Appliquée dans:** Écrans de l'application et base de données

**Ce qu'elle accorde.** Escalate an order to the planner, and use the gap-coverage queue and truck-coverage views (trucks without a reload). Holders also receive the "trucks without reload" reload alerts.

**Où elle est appliquée.** App for the screens (mobile nav, Coverage queue, customer-service mobile model); the database uses it to pick the recipients of the trucks-without-reload notification (notify_trucks_without_reload, via company_users_with_permission).

### Résoudre l'escalade d'une commande

`orders:escalation_resolve`

- **Détenue par défaut:** Admin, Admin entreprise, Planificateur, Dispatcheur
- **Dans le créateur de rôles:** Peut être cochée
- **Appliquée dans:** Base de données et fonctions serveur

**Ce qu'elle accorde.** Resolve an order escalation. Holders are also the recipients of escalation notifications.

**Où elle est appliquée.** Database only, and only as a recipient rule: the escalation notification is sent to users holding this key (company_users_with_permission). It is not a screen or write gate.

### Écrire commandes, clients, devis et sous-traitants

`commercial:manage`

- **Détenue par défaut:** Admin, Admin entreprise, Utilisateur cle, Planificateur, Service client, Commercial
- **Dans le créateur de rôles:** Peut être cochée
- **Appliquée dans:** Base de données et fonctions serveur

**Ce qu'elle accorde.** The commercial write set: create, edit and delete orders (with legs, stops, extras and goods), clients and their contacts, quotes, tenders, subcontractors and their documents, CRM contacts and deals, capacity contracts, client instructions, groupage orders and handling units; read price lists and rate cards.

**Où elle est appliquée.** Database only (policies on dozens of tables, notably the INSERT/UPDATE/DELETE policies of orders, clients, quotes, tenders and subcontractors, and several RPCs and Edge Functions such as client-portal-token). The role builder offers it as a database permission (DRUMA-1595): a custom role needs it, in addition to orders:create, orders:edit or clients:manage, to write these tables.

## Permissions de niveau base de données

Ces permissions nomment un ensemble de rôles de sécurité au niveau des lignes dans la base de données. Sauf mention « sélectionnable », elles ne peuvent pas être données à un rôle personnalisé : un rôle personnalisé qui ne les a pas ne peut pas écrire dans les tables qu'elles protègent, même avec la permission d'application correspondante cochée.

### capi_library:manage

`capi_library:manage`

- **Détenue par défaut:** Admin
- **Dans le créateur de rôles:** Non sélectionnable
- **Appliquée dans:** Base de données et fonctions serveur

**Ce qu'elle accorde.** Druma staff only: edit the shared known-format library that recognises client order messages (SAP IDoc, EDIFACT, JSON freight orders), publish revisions and mark them verified.

**Où elle est appliquée.** The capi_library_* functions and the capi-library-admin Edge Function check it; the library tables have no tenant policy. Held by the platform admin alone, never grantable by a company admin.
