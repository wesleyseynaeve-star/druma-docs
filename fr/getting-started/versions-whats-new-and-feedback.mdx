## Quelle version utilisez-vous ?

Ouvrez le menu de profil dans l'application. En bas s'affiche **Version 3.x.y**. Survolez-la pour voir l'identifiant court du commit et la plateforme (web, application installée, Android ou iOS). Quand vous contactez le support, indiquez ce numéro : il nous aide à retrouver exactement votre build.

Druma publie aussi la version du build web en cours d'exécution dans un petit fichier `/version.json` à l'adresse de l'application, pratique pour un service informatique qui veut la vérifier sans se connecter.

## Ce que signifie le numéro

Druma utilise un numéro simple `majeure.mineure.correctif` qui prolonge la ligne 3.x.

| Partie | Change quand | Exemple |
|---|---|---|
| **Mineure** (le chiffre du milieu) | À chaque version de production régulière, avec nouveautés et corrections | 3.5.0 → 3.6.0 |
| **Correctif** (le dernier chiffre) | Un correctif urgent (hotfix) publié entre deux versions régulières | 3.6.0 → 3.6.1 |
| **Majeure** (le premier chiffre) | Uniquement lors d'un changement de génération voulu et annoncé | 3.x → 4.0 |

Votre application de production affiche toujours une version publiée. Les builds de l'environnement de test de Druma portent le suffixe `-dev` (par exemple `3.6.0-dev.a1b2c3d`) et ne sont pas destinés aux opérateurs.

## Nouveautés et « Livré dans »

L'onglet **Nouveautés** de la fenêtre de retours liste ce que Druma a livré ou développe, filtrable par domaine. Chaque entrée terminée affiche **Livré dans v3.x.y**, la version dans laquelle elle est arrivée. Ce qui est en cours affiche **En cours**. La liste elle-même est décrite dans [Retours et Nouveautés](/fr/planner/whats-new).

## Envoyer un retour

Les retours sont disponibles partout où vous utilisez Druma : le planificateur, l'application chauffeur et les portails client et transporteur. Ouvrez **Envoyer un retour**, choisissez **Bug**, **Suggestion** ou **Question**, décrivez et envoyez. Les étapes détaillées, la détection de doublons et le statut de vos signalements sont dans [Envoyer un retour, voir les réponses et les nouveautés](/en/tools/feedback).

Chaque signalement est envoyé avec la version de Druma que vous utilisiez, la plateforme et la langue de l'écran, afin que l'équipe sache dans quel build le problème est survenu. Il n'inclut pas le user agent de votre navigateur.

## Recevoir un e-mail « corrigé dans »

Quand l'équipe Druma relie votre signalement au changement qui le traite, et que ce changement paraît dans une version publiée, vous recevez un e-mail. L'objet est **Votre retour Druma est dans la v3.x.y** ; le message nomme votre signalement, la version et le titre du changement.

- L'e-mail arrive dans votre langue (langue de l'utilisateur, sinon langue de l'entreprise, sinon anglais).
- Vous recevez un e-mail par signalement, jamais de répétition.
- Un signalement que nous décidons de ne pas traiter (**Ne sera pas corrigé**) n'envoie pas d'e-mail.
- Les signalements ouverts traités par cette version passent à **Terminé** dans **Les miens**, avec une ligne **Corrigé dans** indiquant la version.

<Note>
Si aucun e-mail n'arrive, consultez **Les miens** dans la fenêtre de retours : le statut et la ligne **Corrigé dans** y sont toujours affichés.
</Note>
