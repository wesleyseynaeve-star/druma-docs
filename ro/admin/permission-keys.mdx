Folosiți această pagină când creați un rol personalizat în Setări → Utilizatori → Roluri. Fiecare permisiune indică accesul exact pe care îl oferă, unde o verifică Druma și ce roluri integrate o dețin implicit. Pagina este generată din aceeași configurație pe care rulează aplicația, deci nu se poate abate de la ce face aplicația.

<Note>Numele permisiunilor, zonelor și rolurilor sunt afișate în această limbă. Descrierile detaliate sunt întreținute în engleză.</Note>

## Cum se citește o intrare

Deținută implicit enumeră rolurile integrate care au permisiunea. În editorul de roluri arată dacă un administrator de companie o poate bifa într-un rol personalizat. Aplicată în arată dacă verificarea se face în ecranele aplicației, în baza de date sau în ambele: o permisiune verificată doar în aplicație ascunde butoane, dar nu oprește un apel direct, iar una pe care nu o verifică nimic nu schimbă încă nimic. Necesită și enumeră permisiunile utile doar împreună.

## Comenzi

Creare, editare și ștergere comenzi, plus notele comenzii și câmpurile de preț.

### Vizualizare comenzi

`orders:read`

- **Deținută implicit:** Admin, Admin companie, Utilizator cheie, Planificator, Dispecer, Relații clienți, Raportare, Vânzări
- **În editorul de roluri:** Poate fi bifată
- **Aplicată în:** Ecranele aplicației și baza de date

**Ce acordă.** Opens Operations: the order list, order detail, forwarding and everything shown on an order (legs, stops, references, documents, communications, pallets, templates, e-Transport assignments, status events). Also feeds global search and the sidebar badge counts.

**Unde este aplicată.** The Operations section and its routes ask for it; the database uses it as the row-level read gate on orders and roughly a hundred order-related tables (order_legs, order_references, order_tasks, order_communications, templates, goods lines, status events and more). It does not allow any change.

### Creare comenzi

`orders:create`

- **Deținută implicit:** Admin, Admin companie, Utilizator cheie, Planificator, Relații clienți, Vânzări
- **În editorul de roluri:** Poate fi bifată
- **Aplicată în:** Ecranele aplicației și baza de date
- **Necesită și:** `orders:read`, `commercial:manage`

**Ce acordă.** Create new orders: the New order action, copying an order, creating several orders from a spec, scanning an order document, and creating orders from templates (including scheduled template runs).

**Unde este aplicată.** Both, but in two layers. The screens and the RPCs/Edge Functions behind them (next_order_number, copy_order, create_orders_from_spec, instantiate_order_template, document-scan, order-template-scheduler) check this key. The INSERT into the orders table itself is checked against the database key commercial:manage, which the role builder cannot grant: a custom role holding orders:create but not commercial:manage is stopped at that insert.

### Editare comenzi

`orders:edit`

- **Deținută implicit:** Admin, Admin companie, Utilizator cheie, Planificator, Relații clienți
- **În editorul de roluri:** Poate fi bifată
- **Aplicată în:** Ecranele aplicației și baza de date
- **Necesită și:** `orders:read`, `commercial:manage`

**Ce acordă.** Change existing orders in the places the app lets you edit them: order drawers, subcontracting and carrier assignment, groupage and forwarding panels, VAT and extras, cancelling a sold or subcontracted order, resolving eCMR exceptions and automation jobs, handling client delay notices, approving or rejecting platform proof-of-delivery, e-Transport vehicle change and GPS pause actions.

**Unde este aplicată.** Screens ask for it, and about fifty RPCs check it (cancel_subcontractor, cancel_sell_order, dissolve_groupage, set_preloaded_trailer, resolve_ecmr_exception, approve_transporeon_pod, write_off_remainder and others), as do the transporeon-api, inbound-order-email and client-api-admin Edge Functions. The UPDATE on the orders row itself is checked against commercial:manage (not selectable in the role builder): a custom role needs both.

### Ștergere comenzi

- **Deținută implicit:** Admin, Admin companie, Utilizator cheie, Planificator, Relații clienți
- **În editorul de roluri:** Poate fi bifată
- **Aplicată în:** Nimic nu o aplică în prezent

**Ce acordă.** Intended to allow deleting orders.

**Unde este aplicată.** None today. No screen, RPC, policy or Edge Function reads this key. Deleting an order is decided by the database key commercial:manage (the orders DELETE policy). Granting orders:delete to a custom role changes nothing.

### Vizualizare comenzi proprii

`orders:read_own`

- **Deținută implicit:** Șofer, Client
- **În editorul de roluri:** Poate fi bifată
- **Aplicată în:** Doar ecranele aplicației

**Ce acordă.** The driver or client sees only the orders that belong to them (their own loads or shipments).

**Unde este aplicată.** App marker only: the app uses it to recognise accounts that have no office read access (for example roster-only mode). Row access for drivers is enforced by the orders SELECT policy through driver assignment, not by this key. Exempt from the grant ceiling.

### Corectează date pe înregistrări închise

`data:correct`

- **Deținută implicit:** Admin, Admin companie, Utilizator cheie
- **În editorul de roluri:** Poate fi bifată
- **Aplicată în:** Ecranele aplicației și baza de date

**Ce acordă.** Open the Key User hub and correct allow-listed fields on records the normal workflow no longer exposes (closed trips, delivered orders, invoices, payments, expense decisions), with a mandatory reason and a full audit trail; also resolve key-user fix requests.

**Unde este aplicată.** The Key User route, the closed-record lock host and the correction dialogs ask for it; apply_data_correction, correction_impact_preflight, revert_correction, resolve_key_user_request and some forty correct_* / reverse_* RPCs check it, and the key alone grants nothing: the (entity, column) pair must be in the correctable_fields catalogue and a reason is required.

## Permisiuni la nivel de bază de date

Aceste permisiuni denumesc un set de roluri pentru securitatea la nivel de rând din baza de date. Dacă nu sunt marcate ca selectabile, nu pot fi date unui rol personalizat, deci un rol personalizat fără ele nu poate scrie în tabelele pe care le protejează, chiar dacă permisiunea corespunzătoare din aplicație este bifată.

### commercial:manage

`commercial:manage`

- **Deținută implicit:** Admin, Admin companie, Utilizator cheie, Planificator, Relații clienți, Vânzări
- **În editorul de roluri:** Nu poate fi selectată
- **Aplicată în:** Baza de date și funcțiile de server

**Ce acordă.** The commercial write set: create, edit and delete orders (with legs, stops, extras and goods), clients and their contacts, quotes, tenders, subcontractors and their documents, CRM contacts and deals, capacity contracts, client instructions, groupage orders and handling units; read price lists and rate cards.

**Unde este aplicată.** Database only (policies on dozens of tables, notably the INSERT/UPDATE/DELETE policies of orders, clients, quotes, tenders and subcontractors, and several RPCs and Edge Functions such as client-portal-token). The role builder cannot grant it: custom roles cannot hold it, so a custom role cannot write these tables even with orders:create, orders:edit or clients:manage ticked.
